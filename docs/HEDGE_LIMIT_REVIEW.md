# Почему «Hedge limit reached» появлялся при нулевой позиции

Проверка текущего кода, 23 октября 2026 года. Торговая логика в рамках этой правки UI не изменена.

## Что на самом деле проверял индикатор

В `TradingWorker::publish()` флаг `limited` вычисляется так:

```
target = active ? operation.target : engine.target()
limited = abs(target + selected_options_delta) > min_trade_amount * 0.51
```

Это проверка остаточной дельты после предполагаемого хеджа. Она не сравнивает
фактически занятую сумму с лимитом `maxNotional`: используется расчётный `target`.
Расчёт выполняется также при паузе, до первого Start. Поэтому надпись сама по себе
не свидетельствовала ни о существующем perpetual, ни о достижении долларового лимита.

По текущим местам использования `limited` передаётся в снимок состояния и журнал
решений; сам этот флаг не останавливает торговлю и не определяет размер заявки.
Ограничение размера применяется отдельно внутри `target()`. Обнаруженная ошибка
индикатора сама по себе не доказывает ошибку в отправляемом объёме.

## Откуда берётся ложное срабатывание

`Hedger::target()` сначала ограничивает желаемую позицию значением
`floor_to_step(maxNotional / mid)`, затем округляет её модуль **вниз** до шага сделки.
После такого округления остаток может быть почти в один шаг. Однако `limited`
срабатывает уже при остатке больше **0.51 шага**. В результате флаг смешивает:

1. Невозможность полностью нейтрализовать дельту из-за долларового ограничения.
2. Обычный остаток после округления к допустимому размеру сделки.

Когда дельта меняется внутри одного шага, остаток пересекает порог 0.51 шага.
Именно это даёт мигающую надпись без открытых контрактов.

## Пример по присланному снимку

Цена `81 653.45`, дельты ног `−0.004519` и `+0.003728` BTC, лимит `$815`,
открытый хедж `0`. При шаге `0.0001 BTC` (такой шаг используется и в тестовой
спецификации проекта):

| Величина | Значение |
|---|---:|
| Дельта опционов | −0.000791 BTC |
| Желаемый хедж без округления | +0.000791 BTC, около $64.59 |
| Ограничение по сумме, округлённое до шага | 0.0099 BTC, около $808.37 |
| Рассчитанная целевая позиция | +0.0007 BTC, около $57.16 |
| Остаточная дельта | −0.000091 BTC |
| Порог старого индикатора | 0.000051 BTC |

Остаток больше порога, поэтому индикатор включался, хотя желаемый хедж многократно
меньше лимита, а фактически занятая сумма равна нулю. Для точного воспроизведения
конкретного запуска нужен полученный тогда `min_trade_amount`; пример выше явно
фиксирует это предположение.

## Что ограничивает Max hedge сейчас

Это потолок **общей целевой позиции бота**, а не размер отдельной заявки.
Если долларовый лимит действительно обрезает желаемый хедж, бот может оставить
остаточную дельту. Уже открытая позиция при росте цены может стать дороже лимита:
код предотвращает дальнейшее увеличение, но не ликвидирует её только из-за цены.
Это отдельное действующее правило, оно здесь также не менялось.

## Что изменено только в интерфейсе

Вместо неоднозначного флага теперь всегда показано:

```
Hedge limit: $фактическая_экспозиция / $применённый_лимит
фактическая_экспозиция = abs(bot_inventory) * current_mid
```

При нулевой позиции это `$0 / $815`. Остаток лимита указан в подсказке.
При движении цены числитель может превысить знаменатель; превышение не скрывается.
Пока позиция или цена не синхронизированы, числитель неизвестен (`—`).
Неисполненные заявки и предполагаемые будущие хеджи в этом счётчике не учитываются.
Он не является проверкой доступной маржи или гарантией возможности следующей заявки.

## Предложение для следующего обсуждения

Разделить в backend три независимые величины: фактическое использование лимита,
сокращение желаемой позиции именно из-за `maxNotional` и остаток из-за шага сделки.
Отдельно решить, сохранять ли округление вниз или выбирать ближайшую допустимую
позицию с явным соблюдением лимита. Простое повышение порога `0.51` скроет симптом,
но не исправит смешение понятий. Эти изменения в данном обновлении не выполнялись.

Источники: `src/trading/worker.cpp` (`publish`), `src/engine/hedger.cpp` (`target`,
`evaluate`), `src/engine/domain.cpp` (`Instrument::parse`, `roundDown`).
